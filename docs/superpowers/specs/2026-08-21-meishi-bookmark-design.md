# NEXUA名刺ポケット 設計仕様（初版）

正式名称: **NEXUA名刺ポケット**（作業用コードネーム/リポジトリ名は `meishi-bookmark` のまま。URL変更を避けるため、表示名のみこの名称に変更）

## 概要・目的

NEXUA（デジタル名刺サイト、`nexua.tech`）で名刺を見せられた人が、受け取った名刺URLを後からまとめて見返せるようにするための、NEXUAとは独立した新しいWebアプリ。

## 背景・課題

- 電子名刺を受け取っても、後で見返す方法が分かりにくい
- 「ホーム画面にアイコン追加」で対応しようとすると、複数人と名刺交換した場合（例: 10人なら10個）ホーム画面が埋まってしまい管理しきれない
- 一つにまとまった場所で、受け取った名刺を一覧管理できる仕組みが必要

## 対象ユーザー

NEXUAユーザーに限らない。**名刺を見せられただけの一般の人**（NEXUAのアカウントを持たない人）も利用できることが必須条件。

## 全体アーキテクチャ

```
[NEXUAの名刺画面] --「保存」ボタン--> [NEXUA名刺ポケット（新規タブ）]
                                              ↓ Googleログイン
                                    [お客様自身のGoogle Drive]
                                    （専用シートに自動追記）
                                              ↓
                                    [一覧画面がそのシートを読んで表示]
```

- NEXUA側の変更は最小限：名刺画面に「保存」ボタンを1つ追加するだけ
- 新しいアプリはNEXUAの外側の、完全に独立した静的サイトとして作る（サーバー不要、GitHub Pages等でホスト可能）
- 認証・データ保存は、Googleが提供する仕組み（Googleログイン＋Google Sheets）だけで完結し、運営(NEXUA)側のサーバーやデータベースは一切増やさない

## 技術方針の選定

「お客様自身のGoogleアカウントで」という要望の背景は、**運営(NEXUA)側のサーバー・管理負担を増やしたくないこと**、および**誰が誰の名刺を保存したかという交友関係をNEXUA運営が把握したくない（プライバシー配慮）こと**の両方。

検討した3案：

| 案 | 概要 | 評価 |
|---|---|---|
| **A（採用）** | お客様のGoogle Driveに個人用シートを自動作成 | 運営負担・プライバシーの両方を追加インフラなしで満たす。既存NEXUA(GAS)と同じGoogleエコシステムで技術的にも親和性が高い |
| B | ブラウザのローカル保存のみ、Googleログインは本人確認程度 | 実装は一番簡単だが、端末を変えるとデータが消え「クラウドで管理」という趣旨から外れる |
| C | 新しいクラウド基盤（Firebase等）を新設 | 拡張性は高いが、運営側の新しい管理対象が増え「運営負担を増やしたくない」という要望と逆行する |

→ **案Aを採用**（初版。後述「v2改訂」で案Bとのハイブリッドに変更）

## v2改訂: 認証不要ローカル保存を基本に（2026-08-21）

初版実装後、「慣れていない高齢女性など、何タップもしたり入力したりする操作が負担になる利用者がいる」という指摘を受け、保存フローを見直した。

- **基本（常時）**: 「保存」を押すと**認証なしで即座にその端末のブラウザ内（localStorage）に保存**。1タップで完結し、「保存しました」と表示して終わる
- **オプション（希望する人だけ）**: 一覧画面に「Googleでバックアップ・他の端末と同期する」というボタンを設置。押した人だけGoogleログインに進み、以後は案Aの仕組み（お客様のGoogle Drive内シート）と同期する。初回連携時、それまでローカルに貯まっていたデータもまとめてアップロードする

つまり案B（ローカル保存）を土台にし、案A（Google Drive）を任意のアップグレードとして重ねるハイブリッド構成。運営負担・プライバシー配慮という初版の要件は維持しつつ、初回体験の負担を最小化した。

## 保存フロー（v3）

1. 名刺閲覧者が「保存」ボタンをタップ
2. 新しいタブでブックマークアプリが開く（名刺URL・表示名・タグをクエリパラメータで渡す）
3. **認証なしで即座に**その端末のlocalStorageに1行保存
4. 「保存しました」と、任意入力の「ひとことメモ」欄（会った場所など）、一覧画面（`?`パラメータなしのトップURL）への「保存した名刺の一覧を見る」ボタンを表示
5. メモは「メモを保存」を押した時点で該当エントリに追記される（保存自体はメモの入力有無に関わらずステップ3で完了済み。メモは任意のオプトイン要素）

## 一覧・バックアップフロー（v2）

1. 一覧画面を開くと、ログイン不要でこの端末のローカルデータをすぐ表示
2. 「Googleでバックアップ・他の端末と同期する」ボタンをタップした人だけGoogleログイン画面へ
3. ログイン後、お客様のGoogle Drive内で「NEXUAブックマーク」という専用シートを自動検索。なければ自動作成
4. 初回連携時のみ、ローカルに貯まっていた全件をそのシートへ一括アップロード
5. 以後、一覧表示はGoogle Sheets側の内容に切り替わる（同じ端末で連携済みなら再訪時もこの表示）

## 保存データ項目

| 項目 | 内容 |
|---|---|
| 名刺URL | 保存対象の名刺ページURL |
| 表示名 | 相手の名刺に表示されている名前 |
| タグ | NEXUAのタグ情報（配列、後でタグ絞り込みに使う） |
| 保存日時 | 保存した日時 |
| ひとことメモ | 会った場所など、任意入力のテキスト（v3で追加。保存完了画面での初回入力に加え、v4で一覧画面の各カードからいつでも編集可能に） |
| 写真 | メモ編集欄から追加できる任意の写真（Google連携済みの場合のみ）。Driveへアップロードしたファイルのリンク先URLをシートに保存する |

## 重複対策

初期バージョンでは行わない。同じ人を誤って2回保存しても、両方保存される（YAGNI、後で必要になれば追加検討）。

## 一覧画面

- カード型のリスト表示（表示名・保存日・タグ・メモ）
- カードをタップするとその人の名刺URLが開く
- 検索は名前・タグ・メモを横断（v3で拡張）、保存日順の並び替え
- 各カードから削除可能
- Google連携済みの場合、「Googleスプレッドシートで開く」リンクを表示（そのまま元データのSheetsを直接開き、並べ替え・フィルタ・他の人との共有ができる）
- **ネットワーク図**（保存した人同士のつながりを図で可視化）は初期バージョンでは作らない。ただしタグ・保存日時をデータとして持たせているため、後から追加しやすい設計にしておく

## エラーハンドリング

- Googleログイン失敗 → バックアップボタンを再度押せる状態に戻す
- シート書き込み失敗（回線エラー等） → 「Google連携に失敗しました。もう一度お試しください」と表示（ローカル保存自体は失敗しない）

## 非対象（YAGNI）

- 重複保存の防止
- ネットワーク図表示（初期バージョンでは対象外、データ構造上は拡張可能に留める）
- 複数端末間のリアルタイム同期の独自実装（Google Sheetsの標準的な同期挙動に依存する）
- OAuth審査申請によるGoogle同意画面の本番公開（テストユーザー限定運用のまま。必要性を見て別途判断）

## 未決定・実装計画フェーズで詰める事項

- 具体的なデザイン（NEXUAと統一感を持たせるか、独自ブランドにするか）
- Google Sheets API / Google Identity Servicesの認証スコープと具体的な実装方法
- NEXUA側「保存」ボタンの配置場所（`flipcard.jsx`のどの位置に置くか）
